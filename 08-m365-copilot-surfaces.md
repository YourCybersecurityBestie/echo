# Echo — Microsoft 365 Copilot Surfaces

How Echo shows up inside Microsoft 365 Copilot. Two surfaces, one project, built with the **Microsoft 365 Agents Toolkit** (the VS Code extension formerly called Teams Toolkit).

| Surface | What it does | Who uses it |
|---|---|---|
| **Declarative Agent** | Echo as a chat-style agent inside M365 Copilot, with the same instructions and conversation starters as the Copilot Studio orchestrator | End-users opening Copilot Chat |
| **API Plugin** | Lets *any* M365 Copilot conversation invoke Echo's Publisher API as a tool ("Copilot, turn this article into an Echo episode") | End-users in any Copilot context |

Both ship from a single project under `echo/m365-copilot/`.

---

## Prerequisites

- M365 tenant with **Microsoft 365 Copilot** licenses on at least the developer + demo accounts
- **M365 Agents Toolkit** VS Code extension installed
- Echo's Publisher Function App deployed and `/api/openapi.json` reachable
- Org admin willing to side-load custom apps (Teams admin centre → Manage apps → "Allow custom apps")

```json
{

  "version": "v1.4",
  "name": "Echo",
  "description": "Articles, narrated. Drop a URL and Echo turns it into a 12-minute podcast narrated by Ava and Andrew.",
  "instructions": "$[file('instructions.md')]",
  "conversation_starters": [
    { "title": "Make a podcast", "text": "Make a podcast from this URL:" },
    { "title": "What's in my feed", "text": "What's in my feed?" },
    { "title": "How does Echo work", "text": "How does Echo work?" }
  ],
  "actions": [
    {
      "id": "echoPublisher",
      "file": "plugin.json"
    }
  ],
  "capabilities": [
    {
      "name": "WebSearch"
    }
  ]

```

`instructions.md` reuses the Copilot Studio orchestrator's system prompt (see `01-orchestrator-agent.md`). Keep them in sync — when you change one, change the other.

## `appPackage/plugin.json`

```json
{
  "$schema": "https://developer.microsoft.com/json-schemas/copilot/plugin/v2.2/schema.json",
  "schema_version": "v2.2",
  "name_for_human": "Echo Publisher",
  "description_for_human": "Turn an article URL into a private podcast episode in your Echo feed.",
  "description_for_model": "Use this plugin when the user shares a URL and asks for an audio summary, podcast, or narrated version. Calls the Echo Publisher to synthesize, store, and publish the episode.",
  "namespace": "echo",
  "functions": [
    {
      "name": "PublishEpisode",
      "description": "Publish a previously synthesized episode to a user's private podcast feed.",
      "capabilities": {
        "response_semantics": {
          "data_path": "$",
          "static_template": {
            "type": "AdaptiveCard",
            "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
            "version": "1.5",
            "body": [
              { "type": "TextBlock", "text": "${title}", "weight": "Bolder", "size": "Medium" },
              { "type": "TextBlock", "text": "${description}", "wrap": true },
              { "type": "TextBlock", "text": "${durationSeconds} seconds · Featuring Ava and Andrew", "isSubtle": true }
            ],
            "actions": [
              { "type": "Action.OpenUrl", "title": "▶ Listen", "url": "${listenUrl}" }
            ]
          }
        }
      }
    },
    {
      "name": "ListEpisodes",
      "description": "List the user's most recent published episodes."
    }
  ],
  "runtimes": [
    {
      "type": "OpenApi",
      "auth": { "type": "OAuthPluginVault", "reference_id": "{OAUTH_CONFIG_ID}" },
      "spec": { "url": "apiSpec/openapi.json" },
      "run_for_functions": ["PublishEpisode", "ListEpisodes"]
    }
  ]
}
```

`{OAUTH_CONFIG_ID}` is wired by the Toolkit during `m365agents provision`. Copy from `env/.env.dev`.

## `m365agents.yml` (essentials)

```yaml
version: 1.0.0

provision:
  - uses: aadApp/create
    with:
      name: echo-publisher-${{TEAMSFX_ENV}}
      generateClientSecret: true
      signInAudience: AzureADMyOrg
    writeToEnvironmentFile:
      clientId: AAD_APP_CLIENT_ID
      clientSecret: SECRET_AAD_APP_CLIENT_SECRET
      objectId: AAD_APP_OBJECT_ID
      tenantId: AAD_APP_TENANT_ID

  - uses: apiKey/register      # for the Function key on the Publisher
    with:
      name: echo-function-key
      appId: ${{TEAMS_APP_ID}}
      apiSpecPath: appPackage/apiSpec/openapi.json
    writeToEnvironmentFile:
      registrationId: API_KEY_REGISTRATION_ID

  - uses: file/createOrUpdateJsonFile
    with:
      target: appPackage/plugin.json
      content:
        runtimes:
          - auth:
              reference_id: ${{API_KEY_REGISTRATION_ID}}

  - uses: teamsApp/zipAppPackage
  - uses: teamsApp/update
  - uses: teamsApp/publishAppPackage
```

## Deploy

```pwsh
cd m365-copilot
# Snapshot the live OpenAPI from the Publisher
Invoke-RestMethod https://func-echo-publisher.azurewebsites.net/api/openapi.json `
  -OutFile appPackage/apiSpec/openapi.json

# From VS Code: M365 Agents Toolkit → Provision → Deploy → Publish to Copilot
# Or CLI:
m365agents provision --env dev
m365agents deploy --env dev
m365agents publish --env dev
```

After publish, the Echo agent appears in **Microsoft 365 Copilot Chat → Agents** for everyone in the tenant once an admin approves it.

## Demo paths in M365 Copilot

**Path A — Declarative Agent (chat-first):**
> User opens Copilot Chat → picks "Echo" from agents → drops a URL → gets the listen card.

**Path B — API Plugin (in-context):**
> User in any Copilot conversation: "Take this article — https://… — and turn it into a podcast for me." Copilot picks the `PublishEpisode` plugin, runs it, returns the listen card inline.

Both paths land on the same Publisher Function App, so episodes show up in the same feed regardless of surface.

4. After approval, Echo appears in Copilot Chat → Agents

## Limitations and notes

- **License gate:** Declarative Agents only show up for users with M365 Copilot licenses. Without one, the API plugin path still works inside the Copilot Studio orchestrator and Teams.
- **Auth on the plugin:** v1 uses an API key (Function key). v1.1 should switch to OAuth on-behalf-of so episodes are written under the *user's* identity, not a shared service principal.
- **Don't drift the system prompt.** The Declarative Agent's `instructions.md` and the Copilot Studio agent's "Instructions" must match — they're the same agent, surfaced in two places.
